# 基金挑战 - 关键教训与规则修正 (2026-03-27)

## 🚨 今日错误记录

### 错误 1：机械阻塞 pending 订单
**时间**：14:45 执行门控决策
**问题**：脚本逻辑 `if buy_pending: return True` 把所有 pending BUY 都当作阻塞，不管代码是否相同
**后果**：几乎错过 017192 的买入机会
**修正**：
- 修改 `execute_gate_script_only.py` 的 `classify_pending_constraints` 函数
- 新逻辑：只阻塞**同代码**pending 或**现金不足**情况
- 在途 002611 不阻塞买入 017192（不同代码，现金充足）

### 错误 2：推荐不可买基金
**时间**：14:45 初次决策
**问题**：推荐 019118（纳斯达克科技 QDII），但支付宝不可买
**后果**：用户再次提醒，浪费一轮决策
**修正**：
- 必须从**支付宝可买列表**中选择
- 推荐前必须 `web_search` 验证代码 + 名称 + 平台

### 错误 3：过度依赖量化指标
**时间**：全天多次
**问题**：把脚本输出的置信度、gszzl 当作决策依据，而非参考
**根源**：没有结合宏观、情绪、政策、赛道轮动做综合判断
**修正**：
- 量化指标只占决策权重 20%
- 宏观 (30%) + 情绪 (25%) + 赛道 (25%) 需要人工分析

## ✅ 已修复的代码逻辑

**文件**：`fund_challenge/scripts/execute_gate_script_only.py`

**旧逻辑**（错误）：
```python
if buy_pending:
    return True, "pending_buy_blocks_new_signal"
```

**新逻辑**（正确）：
```python
# 只阻塞同代码 pending
if same_code_pending:
    return True, "same_code_pending_blocks_new_signal"

# 只阻塞现金不足
if intended_buy_amount and cash < intended_buy_amount:
    return True, "insufficient_cash_for_buy"

# 在途订单不阻塞不同代码的新买入
return False, "pending_non_blocking"
```

## 📋 决策框架（必须遵守）

### 多维度分析权重
| 维度 | 权重 | 检查项 |
|------|------|--------|
| **宏观** | 30% | 美联储政策、地缘政治、国内政策 |
| **情绪** | 25% | 北向资金、成交量、周五效应、恐慌指数 |
| **赛道** | 25% | 行业周期、政策催化、持仓相关性 |
| **个体** | 20% | 基金费率、规模、历史回撤、量化指标 |

### 决策流程
```
1. 宏观定性判断（美联储/中东/政策）
2. 市场情绪评估（风险 on/off）
3. 赛道轮动分析（哪个板块受益）
4. 量化数据验证（置信度/gszzl 仅作参考）
5. 人工最终判断
```

### 禁止事项
- ❌ 不能因为 pending 订单就一刀切 HOLD
- ❌ 不能推荐未验证的基金代码
- ❌ 不能把量化指标当决策唯一依据
- ❌ 不能忽略宏观/情绪/赛道的定性分析
