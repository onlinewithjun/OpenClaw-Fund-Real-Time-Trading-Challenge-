# OpenClaw Memory 优化指南

## 目标
- 减少 token 使用量
- 提高 memory 检索效率
- 清理冗余内容
- 实施 aggressive compaction 策略

## 当前问题分析
1. **Daily memory files 过大**：包含详细的系统状态和调试信息
2. **Memory plugin 不可用**：需要修复或替代方案
3. **缺乏自动压缩机制**：手动维护成本高
4. **检索效率低**：依赖全文搜索而非结构化数据

## 优化策略

### 1. Daily Memory 文件优化
- **保留关键信息**：只记录重要决策、用户偏好、技术发现
- **移除冗余内容**：删除系统状态、调试输出、重复信息
- **标准化格式**：使用简洁的标题和要点格式
- **大小限制**：目标文件大小 < 2KB

### 2. MEMORY.md 优化
- **精炼长期记忆**：只保留真正重要的长期信息
- **定期审查**：每7天审查一次，移除过时信息
- **结构化存储**：按类别组织（身份、偏好、技术、项目）

### 3. 高效检索机制
- **利用 qmd 搜索**：已配置成功，提供语义搜索能力
- **关键词标记**：在 memory 文件中添加关键词标签
- **时间索引**：保持日期格式一致性，便于时间范围搜索

### 4. Aggressive Compaction 策略
- **自动清理**：超过7天的 daily memory 文件可归档
- **内容压缩**：移除系统状态、命令输出等临时信息
- **智能摘要**：将多日相关事件合并为单一条目

## 实施步骤

### 立即行动
1. **手动清理现有 daily memory files**
   - 移除所有 "系统状态"、"命令输出"、"调试信息" 部分
   - 保留 "重要决策"、"用户偏好"、"技术发现" 部分
2. **优化 MEMORY.md**
   - 确保只包含长期有价值的信息
   - 按类别重新组织内容

### 中期计划
1. **配置自动 compaction**
   - 创建简单的 PowerShell 脚本进行基本清理
   - 设置定期任务（每周执行）
2. **完善 qmd 集成**
   - 确保 qmd 索引正常更新
   - 测试 memory_search 工具

### 长期目标
1. **开发专用 memory 插件**
   - 替代当前不可用的 memory-core 插件
   - 支持结构化存储和高效检索
2. **实现智能摘要**
   - 自动识别和合并相关事件
   - 生成 weekly/monthly 摘要

## 监控指标
- **Token 使用量**：监控会话 token 使用情况
- **Memory 文件大小**：daily files < 2KB, MEMORY.md < 1KB
- **检索响应时间**：qmd 搜索响应 < 1秒
- **Compaction 效果**：每周减少 30% 的冗余内容

## 备注
- 由于 Windows PowerShell 在处理中文正则表达式时存在兼容性问题，建议采用手动优化 + 简单脚本的方式
- 优先确保 qmd 搜索功能正常工作，这是最有效的 token 节省方案
- 定期审查和手动维护比复杂的自动化脚本更可靠
